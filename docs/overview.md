# ClipLayer サービス概要

## 1. 解決したい課題

中小企業の現場では、**業務 SaaS の一覧画面・ダッシュボードからデータを定期的に転記する作業** が広く発生している。

- EC モール管理画面（楽天 RMS / Amazon Seller / Shopify）→ 注文・在庫・レビュー
- 予約 SaaS（食べログ / ぐるなび予約 / 各種美容予約）→ 予約一覧・顧客
- 業界特化 SaaS（不動産 REINS / 求人 ATS など）→ リスト系画面
- 自社の社内管理画面 → 数値レポート

これらは公式 API が提供されないか、API があっても料金が高すぎる / 機能が足りない。結果として:

- **手作業のコピペ** で日次集計している
- **Selenium / Playwright で内製スクリプト** を組んでいるが、サイト変更で頻繁に壊れる
- **委託会社にスクレイピング BOT を発注** し、月数万円を継続支払いしている
- **iPaaS（Zapier / Make）** ではログイン後画面を扱えず詰む

ClipLayer はこの「ログイン後画面からのデータ取得」を、**コードを書かずに・低コストで・継続的に** 解決する。

---

## 2. 想定ユーザー

### 2.1 1次ペルソナ: 中小企業の業務担当者
- 30〜50 代の事務職・店長・店舗管理者
- Excel は使える、コードは書けない
- 業務 SaaS にログインして毎日確認・転記している
- 「もっと早く済ませたい」「データを Slack に流したい」と思っている

### 2.2 2次ペルソナ: 受託開発会社・コンサル
- 顧客の自動化案件で使う
- 顧客に納品して継続利用させる
- 自分でも他案件で再利用する

### 2.3 3次ペルソナ: 個人事業主・副業
- 1〜2 サイトの定期チェックを自動化したい
- 月数千円なら払ってもいい

## 3. 提供価値

### 3.1 中核価値
- **コードを書かずに DOM 抽出を設定できる**（Element Picker）
- **サイト変更に追従し続ける**（公式 profile の自動更新サブスク）
- **既存ログインセッションをそのまま使う**（認証情報を入力させない）

### 3.2 副次価値
- 取得結果を Webhook / Slack / CSV / 任意 API に送れる
- ローカル保存（IndexedDB）で外部に漏らさない選択肢を持つ
- リスト → 詳細ページの動的巡回で網羅的にデータを取得（Phase 8 で追加）

## 4. 競合と差別化

| カテゴリ | 例 | ClipLayer との違い |
|---|---|---|
| 開発者向けスクレイピング | Playwright / Puppeteer | ClipLayer は GUI 完結・非エンジニア向け |
| 拡張機能型スクレイパー | Web Scraper（webscraper.io）/ Instant Data Scraper | ClipLayer は **profile 配信サブスク** で継続保守。競合は買い切り or 個別設定が基本 |
| iPaaS | Zapier / Make | ClipLayer はログイン後画面を扱える（iPaaS は API 接続のみ） |
| クラウド型 SaaS スクレイパー | Bright Data / Apify | ClipLayer はテナントのセッション利用 = 認証突破不要・対象サイトに弾かれにくい |
| RPA | UiPath / Power Automate Desktop | ClipLayer は導入コストが桁違いに低い（拡張入れて 5 分で動く） |

**最重要差別化**: **公式 profile の継続保守をサブスクで提供** すること。これは買い切り型の拡張やオープンソース系では実現できない。

## 5. MVP 範囲

### 5.1 やること
- 拡張機能（Side Panel + 公式 profile 配信 + Element Picker）
- ログイン・サブスク・device 管理
- 公式 profile 10 サイト分（最初は人気 EC + 予約 SaaS）
- Webhook 送信 + CSV エクスポート
- 破損検知 + 自動更新
- Element Picker（リスト + フィールド指定）

### 5.2 やらないこと（MVP 後・または恒久的に外す）
- 動的ページ巡回（list → detail）: MVP+1（Phase 8）で追加・仕様は [dynamic-traversal.md](dynamic-traversal.md)
- 並列実行・スケジュール実行
- Firefox 対応
- チーム機能（profile 共有・統合請求・組織管理）: 需要次第
- ~~AI 解析~~（仕様撤回・継続コストと開発スコープの両面から MVP では持たない）
- ~~クラウド同期~~（同上・MVP では持たない）

| 項目 | 想定 | 月次 |

### 6.4 「1 拡張 = 1 アカウント = 1 サブスク」の収益効果

明示的なチームプランを作らずとも、企業導入で自然にスケール:

- 個人ユーザー → 1 アカウント / ¥700/月

成立条件: 公式 profile を **10 サイト**、保守追従 SLA を **48h** で維持できること。

## 7. プロダクトの基本思想

### 7.1 設定の自由度より「設定の容易さ」
- 高度な XPath / 正規表現を書ける選択肢は残すが、デフォルトは GUI のみで完結
- 「コードを書く人向け」の機能で複雑にしない

### 7.2 サブスク = 保守料という再定義
- ソフトの所有ではなくサイトカバレッジの保守を売る
- 解約後も既存 profile は動き続ける（自然劣化）
- 解約しても即死しない UX が継続率を上げる

### 7.3 データはユーザーのもの
- デフォルトでローカル保存（IndexedDB）
- 外部送信はユーザー設定（Webhook / API / CSV）に限る
- サーバには抽出データを保管しない（profile 配信と認証のみがサーバ側）

### 7.4 拡張機能の限界を受け入れる
- ソース改造は完全には防げない
- だから防御は「コードの難読化」より「サーバ依存の本質的な価値」に投資する

## 9. 想定リスク

| リスク | 影響 | 対策 |
|---|---|---|
| 対象サイト運営者からのクレーム | 法的・契約的問題 | 利用規約で「個人/法人が正当にアクセス可能な自データの取得のみ」を明示・公開しない |

| 決済プロバイダの業種審査 | サービス停止 | 業種ニュートラルな汎用サービスとして申請（Night Hub と分離する理由の 1 つ） |

## 10. 現時点の定義

ClipLayer は、**ログイン後画面の DOM データを、コードを書かずに継続抽出できる Chrome 拡張機能サブスク** である。価値の中心は「対象サイトの DOM 変化に追従する保守」であり、これがサブスクリプションの正当性と防御の両方を成立させる。
